# Wails Fullstack Development

Guide for building Wails v3 applications with Go backend and web frontend.

**Note:** Wails v3 is currently in alpha. APIs may change.

## Prerequisites

⚠️ **STOP if any prerequisite is missing.**

Wails requires Go, a JavaScript runtime, and the Wails CLI. Verify all are installed:

### Go 1.21+

```bash
go version
```

If not installed:
- macOS: `brew install go`
- Linux: `sudo apt install golang` or `sudo dnf install golang`
- Windows: Download from https://go.dev/dl/

### Bun or npm

```bash
bun --version
# or
npm --version
```

If not installed:
- Bun: `curl -fsSL https://bun.sh/install | bash`
- npm: Comes with Node.js from https://nodejs.org/

### Wails CLI

```bash
wails3 version
```

If not installed:
```bash
go install github.com/wailsapp/wails/v3/cmd/wails3@latest
```

## Project Structure

### Option A: Standard Wails (Quick Start)

Generated by `wails3 init`:

```
myapp/
├── main.go           # Entry point + services
├── greetservice.go   # Service (same package)
├── frontend/
└── build/
```

Simple, good for small apps or prototypes.

### Option B: Organized Structure (Recommended for Growth)

```
myapp/
├── main.go              # Entry point, window setup, service registration
├── internal/            # Domain logic (no Wails dependencies)
│   └── feature/         # One package per feature
├── service/             # Wails bindings (thin layer)
├── pkg/                 # Shared utilities (optional)
├── frontend/
└── build/
```

**Why Option B:**
- `internal/` keeps domain logic pure and testable
- `service/` is a thin binding layer only
- Easy to add features without entanglement

To convert from Option A to B:
```bash
mkdir -p internal service pkg
mv *.go service/  # except main.go
# Update package declarations in each file
```

## Create New Project

```bash
wails3 init -n myapp -t react-ts
cd myapp
mkdir -p internal service pkg
```

## Feature Development Patterns

### Frontend-Only

Client-side tools without backend logic.

- Add page: `frontend/src/pages/Feature.jsx`
- Add route in router configuration
- No Go changes required

Use for: encoders, formatters, calculators, syntax highlighters.

### Backend-Only

Go services without UI components.

- Domain types: `internal/feature/types.go`
- Service binding: `service/feature.go` with public methods
- Register in `main.go`: `app.RegisterService(application.NewService(yourService))`

Use for: background workers, IPC handlers, data processing.

### Full-Stack

Go service connected to frontend.

| Step | Location | What |
|------|----------|------|
| Domain logic | `internal/feature/` | Pure Go, no Wails imports |
| Service binding | `service/feature.go` | Wraps internal, exposes to frontend |
| Register | `main.go` | `app.RegisterService(application.NewService(...))` |
| Frontend page | `frontend/src/pages/Feature.jsx` | UI component |
| Call backend | Frontend | `import { FeatureService } from "../bindings/yourmodule"` |

## Backend Service Pattern

```go
// internal/feature/types.go
package feature

type DecodeRequest struct {
    Token string `json:"token"`
}

type DecodeResponse struct {
    Header  map[string]interface{} `json:"header"`
    Payload map[string]interface{} `json:"payload"`
    Error   string                 `json:"error,omitempty"`
}
```

```go
// internal/feature/service.go
package feature

type Service struct{}

func (s *Service) Decode(token string) DecodeResponse {
    // Pure domain logic here
}
```

```go
// service/feature.go
package service

import "yourapp/internal/feature"

type FeatureService struct {
    svc feature.Service
}

func NewFeatureService() *FeatureService {
    return &FeatureService{svc: feature.Service{}}
}

func (s *FeatureService) Decode(token string) feature.DecodeResponse {
    return s.svc.Decode(token)
}
```

Register in `main.go`:
```go
app.RegisterService(application.NewService(service.NewFeatureService()))
```

**Error handling:** Return errors in response structs with `Error` field. Don't panic.

## Frontend Pattern

```jsx
// frontend/src/pages/Feature.jsx
import { FeatureService } from "../bindings/yourmodule";

function Feature() {
    const handleAction = async () => {
        const result = await FeatureService.Decode(input);
        if (result.error) {
            // Handle error
        }
        // Use result
    };
    // ...
}
```

**Layout pattern:** Header (title + purpose) + Controls (options + actions) + Workspace (content panes).

## Running & Testing

**Development:**
```bash
wails3 dev
```

Frontend hot-reloads. Backend changes require restart.

**Browser testing:**

Use the `rodney` skill for automated browser testing:

```bash
rodney start
rodney open http://localhost:5173
rodney wait ".your-component"
rodney click "#submit-button"
rodney assert 'document.querySelector(".result").textContent' 'Expected'
rodney stop
```

If rodney skill is not installed:
```bash
npx skills add https://github.com/vuon9/agent-skills --skill rodney
```

**Desktop vs Browser:**

Most features work identically in both modes. Desktop-only features:
- Global hotkeys (system-wide shortcuts)
- System tray integration
- Native window controls

Test desktop-only features in desktop mode, not browser.

## Common Mistakes

| Mistake | Fix |
|---------|-----|
| Service not found | Register in `main.go`: `app.RegisterService(...)` |
| Binding not updating | Rebuild: `wails3 build` regenerates bindings |
| Frontend not connecting | Check `wails.json` devServerUrl matches Vite port |
| Using desktop-only APIs in browser | Check context before using Events, SystemTray |
| Domain logic in service layer | Move to `internal/`, keep `service/` thin |
