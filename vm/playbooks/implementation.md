# Implementation

For work that builds or changes behavior. Copy these steps in order.

1. Match the entry.
   - Requirements clear. Open brainstorming and run it to a design before coding.
   - Foggy, or bigger than one session. Open wayfinder, chart the map, and solve decision tickets one at a time until the route is clear.
   - Otherwise. Clarify with the user until requirements are clear enough to start.
2. Design before code. Name the data shape or behavior before writing logic.
3. Prove the behavior. For a user-facing feature, write or run the behavior/feature tests first.
   <!-- EDIT: behavior-test --> Replace this line with your behavior-test command or approach.
4. Prove the scoped work with TDD. For unit or functional scope, use the superpowers `test-driven-development` skill.
5. Verify against the real artifact before declaring done.
