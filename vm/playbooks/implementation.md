### Implementation

**You build the behavior, and prove it.**

Use for work that builds or changes behavior.

- **Match the entry.** Requirements clear? Open `brainstorming` and run it to a design. Foggy or bigger than one session? Open `wayfinder` and resolve the route. Otherwise, clarify with the user until the scope is clear enough to start.
- **Design before code.** Name the data shape or behavior first. Pick its organizing structure before writing logic.
- **Prove the behavior.** For a user-facing feature, write or run the behavior/feature tests first.
  <!-- EDIT: behavior-test --> Replace this line with your behavior-test command or approach.
- **TDD for scope.** For unit or functional scope, write the test first with `test-driven-development`.
- **Verify against the real artifact.** Not "it compiles". Run the thing and prove it.
